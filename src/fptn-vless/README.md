# fptn-vless

Консольная утилита: подключается к FPTN по токену и отдаёт туннель в локальную
сеть как **VLESS-inbound**. На ПК не создаётся адаптер, не меняются маршруты и
DNS: туннель заканчивается в userspace-стеке (lwIP). Закрыли окно, и система
осталась как была.

```
LAN-клиент --VLESS--> fptn-vless.exe --[lwIP]--> libfptn --TLS--> FPTN-сервер
```

## Как это работает для пользователя

1. Запустите `fptn-vless.exe` один раз (двойной щелчок или из консоли). Программа
   создаст ярлык **fptn-vless** на рабочем столе, откроет в браузере панель
   управления `http://127.0.0.1:10801/` и поселится в трее.
2. В панели вставьте токен (любой длины, пробелы и переносы строк не мешают),
   нажмите «Загрузить серверы», затем «Подключиться к самому быстрому» или выберите
   сервер. Галка «Запомнить» сохраняет токен зашифрованным (DPAPI, только для вашей
   учётной записи Windows) в `%APPDATA%\fptn-vless\settings.json`.
3. Панель покажет ссылку `vless://…` с IP вашего ПК в локальной сети и кнопкой
   «Копировать». Вставьте её в Incy и т. п.
4. Дальше достаточно ярлыка: если программа уже в трее, он просто откроет панель;
   если не запущена, запустит её, сама подключится к сохранённому серверу
   (или к самому быстрому) и откроет панель.
5. Выход: правый щелчок по значку в трее → «Выход» (или Ctrl+C, если запущено из консоли).

Панель умещается на одной странице без прокрутки: слева список серверов (по
пингу, с цветной шкалой), справа настройки:

* **Режим подключения**: «Лучший по пингу» (программа сама держится на самом быстром
  сервере) или «Выбранный» (только сервер, на который вы нажали).
* **Если сервер упал**: «Перейти на другой» или «Ничего не делать».
* **Порт VLESS**: можно задать свой. Если порт занят, остаётся прежний.
* **Брандмауэр**: кнопка добавляет правило для входящих подключений на этот порт
  (спросит UAC). Рядом показано, открыт порт или нет.
* Ввод/смена токена, «Отключиться», повторный замер, проверка туннеля, журнал.

Настройки (режим, поведение при падении, порт, последний сервер) запоминаются.
Адаптеры, маршруты и DNS Windows не затрагиваются.

Параметры командной строки нужны только для особых случаев (`--access-token`,
`--token-file`, `--server`, `--port`, `--dashboard-port`, `--no-tray`, `--no-shortcut`,
`--no-browser`, `--verbose`, см. таблицу ниже).

## Использование из консоли

```
fptn-vless.exe                              # панель откроется в браузере
fptn-vless.exe --token-file token.txt       # токен из файла (не запоминается)
fptn-vless.exe --server Finland-2 --port 10800
```

| Опция | По умолчанию |
|---|---|
| `--listen` | `0.0.0.0` |
| `--port` | `10800` |
| `--bypass-method` | `sni-spoofing-yandex-26-4` |
| `--connection-strategy` | `rolling-tunnel` |
| `--scan-interval` | `300` (секунд) |
| `--no-failover` | выкл |
| `--dashboard-port` | `10801` |
| `--no-tray`, `--no-shortcut` | выкл |
| `--no-browser`, `--verbose` | выкл |
| `--link-host` | авто (IP в LAN), можно задать вручную |
| `--sni`, `--mtu-size`, `--uuid` | как в `fptn-client-cli` |

## Самопроверка и мульти-подключение

После подключения программа проверяет туннель (TCP к 1.1.1.1 и к имени example.com
через туннель) и пишет результат в журнал панели: так видно, что сломано (сервер
не отвечает, не работает DNS). DNS внутри туннеля дублируется публичным резолвером.

Каждые 5 минут (`--scan-interval`, 0 = выключить) программа заново замеряет отклик
всех серверов (без входа в аккаунт, текущую сессию это не трогает) и сама
переключается на лучший, если:

* текущий сервер не ответил 2 замера подряд и через него не открывается TCP-соединение,
  либо туннель упал и не восстановился за 20 с, или
* он медленнее лучшего более чем в 1.5 раза **и** минимум на 150 мс (гистерезис).
  Перед переключением замер подтверждается повторно через 30 с.

В режиме «Выбранный» (включается и кнопкой «Подключиться» на сервере, и `--server`)
программа остаётся на нём; при падении уходит только если включено «Перейти на другой». Новое соединение сначала поднимается и
только потом заменяет старое; открытые VLESS-соединения при смене сервера
обрываются (клиент переподключается сам), ссылка и UUID не меняются.
`--no-failover` отключает автопереключение (настройка «Если сервер упал» тогда недоступна).

## Ограничения

* Только TCP. VLESS-UDP (QUIC/HTTP3 с клиентов) не поддержан, приложения откатятся на TCP.
* Только IPv4 цели. Домены резолвятся внутри туннеля через DNS сервера FPTN.
* VLESS без TLS: только для доверенной LAN. Не пробрасывайте порт наружу.
* Брандмауэр Windows спросит разрешение на входящие: разрешите (и для частных, и для общедоступных сетей, если Wi-Fi помечен как публичный).

## Если телефон не подключается

1. Телефон и ПК в одной сети (не гостевой Wi-Fi, не мобильный интернет).
2. `ipconfig` — IP должен совпадать с тем, что в ссылке (`--link-host`, если нет).
3. Проверка порта с ПК: `Test-NetConnection <ip> -Port 10800`.
4. Правило брандмауэра (PowerShell от администратора):
   `netsh advfirewall firewall add rule name="fptn-vless" dir=in action=allow protocol=TCP localport=10800 profile=any`
5. В консоли при первом соединении телефона появится строка
   `New VLESS client connected from <ip>` — если её нет, пакеты не доходят
   (сеть/брандмауэр); если есть, а интернета нет — смотрите предупреждения ниже неё
   (UDP и IPv6 цели не поддержаны).

## Тесты

`fptn_vless_loopback_test` проверяет весь путь VLESS -> lwIP -> IP-пакеты -> второй
lwIP без настоящего FPTN-сервера: эхо, 4 МиБ вниз/вверх с проверкой данных,
8 параллельных потоков, неверный UUID, таймаут, закрытый порт, сброс при смене
сервера. `fptn_vless_failover_test` проверяет логику выбора/переключения серверов, `fptn_vless_dashboard_test` — страницу управления и её защиту (Host и CSRF), `fptn_vless_app_test` — жизненный цикл приложения (токен, сканирование, подключение, смена сервера, запоминание) на подставных серверах.
